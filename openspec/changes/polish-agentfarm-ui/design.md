## Context

The Agent Farm desk-pet UIs (`src/tab5_agentfarm/feed_ui_tab5.cpp`,
`src/cardputer/feed_ui.cpp`) work but look unrefined next to the buddy
dashboard (`src/tab5/ui.cpp`), which already defines a strong visual language:
a `th::` three-elevation dark palette, Claude coral accent, semantic state
colors, rounded lift-border cards, a framed clawd GIF avatar, and anti-aliased
VLW fonts. The transport/feed/mood behavior is correct and stays as-is; only the
presentation needs to reach that quality bar. Pain points named by the user:
overall layout/composition, the avatar area, color/texture, and the header bar.

## Goals / Non-Goals

**Goals:**
- Bring the Tab5 (primary) and Cardputer agent-farm UIs to the buddy dashboard's
  visual quality on the four named axes: layout, avatar framing, color/texture,
  header/status bar.
- Reuse the buddy dashboard's design tokens and component patterns so the two
  product surfaces feel like one family.
- Crisp typography on Tab5 (VLW smooth fonts) with a safe fallback.

**Non-Goals:**
- No change to polling, dedup, mood semantics, or the shared transport
  (`src/agentfarm_feed/`).
- No new interaction (keyboard reply, voice, approvals) — presentation only.
- No pixel-cloning the buddy dashboard's session/transcript layout; the feed has
  a different data shape (independent trigger firings, not one chat stream).

## Decisions

### D1 — Reuse the buddy visual tokens by copying, not extracting a shared lib
Copy the `th::` palette and the `card()/pill()/statusDot()` helper patterns into
the agent-farm UI files (Tab5 already does this partially). Rationale: the repo
convention is one isolated source set per target (stackchan/tab5 share nothing
but `platformio.ini`); a shared UI lib would couple the agent-farm build to the
buddy firmware and risk regressions there. Alternative (shared `ui_theme.h`)
rejected for that coupling. The shared *transport* stays in `agentfarm_feed/`;
only the *look* is duplicated, which is cheap and stable.

### D2 — Tab5 layout mirrors the dashboard geometry
Sidebar (≈300px PANEL) + main (BG) split with consistent `PAD`, a header band
(title + state chip + divider), and the feed as an aligned card column. Reuse
`ui.cpp`'s spacing constants and `card()/pill()` so alignment and elevation
match. Full-frame PSRAM sprite with event-driven redraw is already in place.

### D3 — Avatar gets a deliberate stage + balanced whitespace
Seat the clawd GIF the way `ui.cpp` does (fixed center, framed, mood tag below),
removing the current floating-with-dead-space look. Keep the GIF fast-push path
(`avatarPushDirect`) for animation without full-frame redraws.

### D4 — VLW smooth fonts on Tab5, built-in fallback
Adopt the dashboard's VLW faces (mono / proportional / bold) loaded from
LittleFS `/fonts` (generated by `tools/make_vlw.py`, pushed via `uploadfs`),
falling back to the built-in GFX fonts when `/fonts` is absent — exactly the
`uifont()` pattern in `ui.cpp`. Alternative (keep built-in GFX fonts) rejected:
the blocky fonts are a named pain point and the smooth faces are the single
biggest perceived-quality lift.

### D5 — Cardputer is a constrained restyle, not a port of the big layout
The 240×135 screen can't carry the sidebar+main composition. Apply the same
palette/accent + compact cards + tidy header within the small canvas; keep the
built-in font (VLW is overkill at this size). Legibility beats density here.

## Risks / Trade-offs

- [VLW fonts require `/fonts` on LittleFS + `uploadfs`] → graceful fallback to
  built-in fonts if absent; document the `make_vlw.py` + `uploadfs` step.
- [Full-frame DSI pushes on Tab5 are expensive] → keep redraws event-driven
  (dirty flag) and animate the GIF via the avatar fast-push path, as the buddy
  dashboard does.
- [Over-styling the 240×135 Cardputer hurts legibility] → cap card chrome,
  prioritize text contrast; treat Cardputer as "lightly themed", not a mini
  dashboard.
- [Copying tokens duplicates the palette] → small, stable surface; acceptable vs
  the coupling cost of a shared lib (D1).
